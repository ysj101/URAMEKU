# CASE02の見え方のミニ実験

## Sub-features

欲しかった商品と8,000円では買わなかった理由、直感で選ぶ4択、資料の開示、2つの見せ方の比較、判断を変える・維持する、最後のコラムと出典。

## How to get to it (user POV)

事件一覧からCASE02を選ぶ。最初にミニ実験が出る。4択から1つ押すと、その場で最初の選択が記録される。調査資料の一覧から価格履歴と販売記録を開き、「戻る」で閉じる。比較後の選択と理由を記録すると、完了の通知とは別の補足欄に解説とコラムが出る。調査はデスクのタブから続ける。

## Driving it with Playwright

`URAMEKU_SHOTS=/tmp/urameku-case02-shots npm run test:e2e -- e2e/case02-experiment.spec.ts --project=chromium`。1280x800と390x844の両方をテスト内で指定する。通常割当の提示Bと、初期条件だけを変えた提示Aを確認する。Aは判断を維持し、Bは変更する。最初と比較後の選択を保存し、reload後もコラムが見えることを確かめる。

共通の状況はA/Bとも同文で見える。初回に反対の条件やコラムを出さない。比較段階で2条件を出し、記録後だけ参照価格と1985年の研究、セールと参照価格についての公式解説、2017年の受賞理由と3つの出典を出す。効果そのものが受賞したとは書かない。ミニ実験のsection内で主ボタンは最大1つ。比較の記録ボタンだけがprimaryで、初回・資料待ち・完了は0個。画面全体の主ボタンや「次にやること」の案内は別PRの担当とし、この検証では数えない。文字の矩形、祖先の切り取り、横のはみ出しも確かめる。

## Gotchas

割当は事件IDで固定され、reloadで変わらない。AのテストはcreateProgressで選択前の空の状態を作り、条件IDだけを変えて検証専用コンテキストへ入れる。実ユーザーの保存データに対して使わない。画像はリポジトリ外に保存する。Chromiumを起動できないサンドボックスでは実行待ちとする。手動で4段階の画像を確認するまで、画面の見た目は確認済みとしない。

`URAMEKU_SHOTS`指定時は4段階をfullPageで保存する。ファイル名は`B-01-experiment-start-1280x800.png`、`B-02-initial-choice-made-1280x800.png`、`B-03-compare-1280x800.png`、`B-04-final-column-1280x800.png`。390x844では寸法部分を変え、提示Aでは先頭をAにする。
