# 調査画面の検証

## Launch

リポジトリのルートで実行する。

```sh
export PATH="$HOME/.nvm/versions/node/v26.12.1/bin:$PATH"
npm run dev -- --host 127.0.0.1 --port 53291 --strictPort
```

## Doctor

- サーバーが53291番で応答することを確認する。
- ブラウザーを起動できるか確かめる。起動できなければ制約を報告する。
- 1280×800と390×844の両方で確認する。
- 既存の保存記録を消さず、新しい空のブラウザーコンテキストを使う。

## Drive

1. `http://127.0.0.1:53291/#/play/case-01` を開く。
2. 最初の画面に予算と「次にやること」のボタンが見えるか確認する。
3. カードのprimaryを押して「キャンペーン広告」を読み、「戻る」で閉じる。
4. 問1はデスクに出ているので、カードのボタンは控えめになる。答えを選び、カードが案内する未読資料を開いて読む。
5. 残りの問いも同じ操作で記録する。カードが証拠ボードを案内するか確認する。
6. カードからボードを開く。開くとカードは控えめになる。文に証拠を添え、文の扱いを選び、「文と証拠を記録」を押す。
7. すべての文を記録すると、報告ボタンだけがprimaryになるか確認する。
8. 報告をまとめて提出し、結果まで進む。
9. 各段階で、押せる可視の `.btn.primary`（無効化を除く）が多くても1つで、それが次の操作であること、横スクロールがないことを確認する。
10. 「残っていることの一覧」を開くと、残りの問い・ボード・未読資料へのボタンが出るか確認する。
11. 「遊び方」から全体の手順と「この事件を最初から」に辿り着く。
12. やり直し確認を「やめる」で閉じ、記録が残ることを確認する。
13. 別の空コンテキストでは、未完了でも報告へ進めることを確認する。
14. CASE02〜05でも各デスクへ移れることを確認する。

答えの確認には `docs/walkthrough/case-01.md` を使う。事件データや答えを変えない。

## Evidence

- 開始、最初の資料のあと、問いの記録後、ボード記録後のスクショを両幅で残す。
- 変更前と並べ、ボタン数と案内の見え方を確認する。
- 実行したコマンド、結果、実行できなかった確認を記録する。
- 自動確認は `CI=1 npx playwright test e2e/case01-declutter.spec.ts --project=chromium --project=mobile-chromium`。
- Playwrightは4175番でbuildとpreviewを起動し、CIでないときは既存サーバーを再利用する。別のワークツリーが4175番を使っていると、そのコードを検証してしまう。`CI=1` を付けるか、ポートだけ変えた一時設定（コミットしない）で `-c` を指定する。

## Cleanup

- 自分が起動したサーバーとブラウザーコンテキストを閉じる。
- ユーザーの保存記録や既存のサーバーは消さない。
