# ウラメク V2 — 初見利用者テスト計画

**実施状況：未実施 0/5人。** この計画・観察シートやサンプルJSONの存在は実績ではない。目的はゲームの操作と高難易度の体験を改善することで、参加者の特性を測ることではない。旧計画は `../archive/game-v1/qa/user-test-plan.md`。

## 対象と同意

初見利用者5人以上。16歳以上でパズル/ニュース等に関心がある人を想定し、スマートフォン2人以上・PC2人以上を目安にする。開発者・レビュアーの自動/手動QAを人数に含めない。`user-test-consent.md` を読み、口頭同意を記録する。参加者番号P01等を用い、氏名・所属・連絡先・年齢・性別・録音・録画を収集しない。途中終了・回答辞退を認める。

## 事前準備

- ビルドのcommit SHA、ローカル/配信の別、端末/OS/ブラウザ/入力方法/画面幅を記録する。
- 前の参加者の履歴を削除し、音量・Reduced Motionは参加者の希望に合わせる。
- 参加者が読むチュートリアル以外に、操作の答えや必要資料・推奨方針を教えない。

## 60分の進行

1. 0〜5分：同意、すべて架空であること、評価対象はゲームであること、途中終了できることを伝える。
2. 5〜15分：チュートリアルを自分で読む。詰まりを記録する。
3. 15〜35分：CASE 01。資料・根拠・留保を読む操作を観察する。
4. 35〜50分：心理実験のCASE 02/03または意思決定のCASE 04/05。参加者間で割当を分け、全体で3方式を観察する。時間不足なら無理に完走させず未完了として記録する。
5. 50〜60分：本人の言葉で振り返りを聞く。初回と更新後の判断・維持した理由も、同意のある発言だけを引用する。

同一画面で3分以上止まり「分からない」と明言した、リセット/保留へ2分以上到達できない、または不具合で進行できない場合にだけ最小の助け舟を出す。内容・時刻・理由を記録する。答えや望ましい方針は教えない。中断希望は助け舟ではなく終了と記録する。

## 観察と質問

| 観察対象 | 記録する事実 |
| --- | --- |
| 操作不明か推論が難しいか | 画面/操作/時刻、rule_unclear / ui_unclear / content_unclear / reasoning_hard / bug |
| 情報の読み違い | どの記述・対象・出典をどう読んだかの発言、どの追加情報で見直したか |
| 初回と更新 | 維持/変更の理由、当時分かっていたこと、反証・前提・保留の扱い |
| 楽しさと難易度 | 5段階の楽しさと具体的な瞬間、難しかったが納得できた点、納得できなかった点 |
| 進行・回復 | 所要時間、完走/中断、根拠不足後の次の操作、助け舟、リセット |
| 可読性 | 紙の装飾、文字200%、ボタン、読み上げ/キーボードでの困難 |

質問例：「何を確認できて、何がまだ分かりませんか」「最初の判断を維持/変更した理由は何ですか」「別の目的なら別の方針も成り立ちますか」「難しかったのは操作ですか、推理ですか」「いちばん楽しかった/退屈だった瞬間はどこですか」。選んだ方針を採点せず、人格・能力・バイアスの強弱を記録しない。

## 記録・集計・改善

観察者は `user-test-session-template.md` にメモし、終了後15分以内に既存 `qa/user-tests/session-template.json` を実際の記録としてコピーする。ゲームV2と対象事件revisionは `build` と `observer_notes` に記載し、初回/更新・難易度の発言は `interview` / `observer_notes` に引用として残す。既存JSON schema_version:1は観察記録の形式でありゲームV2の番号とは別。例示データは実績に含めない。

`npm run summarize:user-tests` で完走率・時間・楽しさ・詰まりを集計する。自動集計は観察と引用の代わりではなく、推理の難しさを欠陥と断定しない。重大なUI進行阻害・根拠の不公平・誤解を優先して改善し、単純三択や計算課題へ戻さない。正解キーや分母をテストに合わせて変えない。

5人の記録・3方式を含む観察・採否と改善の証跡が揃ってから人手要件の完了を判断する。実施できない限り #114 と親 #99 の人手要件はpendingとする。
