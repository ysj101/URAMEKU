# 攻略・編集者向け答え合わせ資料（内部用）

**この資料はリリース成果物に含めない。** プレイヤー向けではなく、事件データの編集者・QA・レビュアーが答え合わせと難易度調整に使う内部資料である。`public/` や配布物にコピーしないこと。

## ネタバレ注意

`case-01.md` 〜 `case-05.md` には 5 事件すべての必要証拠・照合・検証メモの正解・見出しの正解順序が書かれている。未プレイのまま遊び心地を確認したい人は読まないこと。

## 構成

| ファイル | 内容 |
| --- | --- |
| `README.md` | この文書 |
| `case-NN.md` | 事件ごとの答え合わせ。自動生成セクション + 手書きセクション |
| `../../scripts/generate_walkthrough.mjs` | 自動生成セクションを `data/cases/*.json` から作るスクリプト（Node 標準モジュールのみ） |

各 `case-NN.md` は 2 層になっている。

1. **自動生成セクション**（`<!-- generated:start -->` 〜 `<!-- generated:end -->`）
   `data/cases/case-NN.json` から機械的に導ける情報: 資料一覧と役割、必要証拠、照合ペア、検証メモの正解・単位・受理範囲、正解断片の順序と本文、最小コスト（必要証拠 ∪ 照合資料のコスト合計）、残予算、`docs/GAME_RULES.md` 7 章の配点で計算した到達可能な最高点、外れ資料を 1 件開いた場合の可否。
   **手で編集しない。** JSON を直した後に再生成する。
2. **手書きセクション**（マーカーの外側）
   推奨調査順序、コスト最小値での到達手順と最終スコア、別解の検討、詰みパターン、編集者メモ。スクリプトはこの部分を上書きしない。

## 使い方

```bash
# data/cases/*.json を変更したら再生成する（手書き部分は保持される）
npm run walkthrough

# 生成物が最新か確認する（差分があれば終了コード 1）
npm run walkthrough -- --check
```

新しい事件 JSON を追加して実行すると、手書きセクションのひな形付きで `case-NN.md` が新規作成される。

## 読み方の注意

- 「最小コスト」はコスト計算上の下限で、**情報として必要な資料**は別に判断が要る。case-03 は検証メモの答えが必要証拠外の資料 `other` にしかないため、実際にクリアするための最小コストは生成値より 1 大きい。詳細は各ファイルの手書きセクションを参照。
- 「別解の検討」に挙げた組み合わせはすべて**現行 JSON では不正解**である。正解キーをテストや感覚に合わせて変更しないこと（`AGENTS.md`）。別解を正解として認めたい場合は、`docs/GAME_RULES.md` 4 章に従い JSON モデル側（複数の有効な照合など）を拡張する別 Issue として扱う。
- 5 事件とも 100 点には到達できない。予算ボーナス 6 点には残予算 3 が必要だが、有料の必要資料 3 件に対して予算が 4〜5 のため、残りは最大 2（case-04）。これは配点の仕様であり不具合ではない（`GAME_RULES.md` 7 章「100 点の達成は必須ではない」）。

## 5 事件の要約

| 事件 | 予算 | 最小コスト | 最高点 | 外れ 1 件で詰むか | 備考 |
| --- | --- | --- | --- | --- | --- |
| case-01 | 4 | 3 | 96 | 詰まない（2 件で詰み） | 照合 `paid × retained` が別解として強い |
| case-02 | 4 | 3 | 96 | 詰まない（2 件で詰み） | 無料の `poster` を採用し忘れると照合不可 |
| case-03 | 4 | 3（実質 4） | 96（実質 94） | **`comments` で詰む** | 検証メモ `support` の答えが `other` にしかない |
| case-04 | 5 | 3 | 98 | 詰まない（全部開ける） | 照合 `spent × switch` が正解と対称で区別不能 |
| case-05 | 4 | 3 | 96 | 詰まない（2 件で詰み） | 無料の `graphic` を採用し忘れると照合不可 |
