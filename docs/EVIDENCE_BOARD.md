# 証拠ボードの改善方針

2026-10-30。ウラメクのゲームV2に適用する。スターターの機能変更であり、本番承認を意味しない。

## 目的

資料A・資料B・関係名を登録する操作を、文の気になる部分に証拠を添え、資料から言える内容へ組み立て直す操作に変える。操作の目的は明示し、証拠の発見と説明の組み立てはプレイヤーに任せる。

完成した答えを並べるだけの問題にはしない。文の部分ごとに対象・比較基準・費用・確かさを組み合わせ、資料の一節を選ぶ。ドラッグは必須にせず、タップとキーボードで同じ操作ができる。既存の情報解読メモ・実験・意思決定は残す。

## 共通の流れ

1. 確かめる文を選ぶ。すべての編集可能な部分を同じ見た目で示し、正解箇所の強調はしない。
2. 文の下線が付いた部分を押して、その部分の内容を組み直す。
3. 読んだ資料から一節を選び、その文に添える。選べる資料に正解だけを並べない。
4. 「そのまま残す」「内容を直す」「まだ判断できない」を選び、文と証拠を記録する。
5. 記録した文・扱い・証拠を報告画面にまとめる。提出後に、資料との食い違いと不足を確認する。
6. 解説を開くと、問いごとの説明を読むことができる。提出を取り下げて修正できる。

調査中の件数は操作の記録数であり、正しい数ではない。正解表示で総当たりを誘導しない。「記録あり」から内容の正しさを推測させない。正しい記述をそのまま残す課題、判断できないと結論する課題も用意する。

## 事件ごとの課題

| 事件 | 組み立てる内容 | 判定の対象外 |
| --- | --- | --- |
| 01 消えた55人の利用者 | 有料移行者の90%と、登録者全体の45%を区別する | 広告の効果や担当者の意図の断定 |
| 02 半額セールの値札 | 発売時との比較と最近の実売価格を区別する | 買うか見送るかという反応 |
| 03 8割が支持の正体 | 任意回答者内の結果と利用者全体の未確認事項を分ける | サービスを支持するかどうか |
| 04 取り戻せない開発費 | 過去費用・今後の費用・便益見積りとリスクを分ける | 継続・切り替え・停止・保留の優劣 |
| 05 急上昇するグラフ | 数字の変化・縦軸・原因を断定できないことを説明する | 掲載・追加調査・保留の優劣 |

今回の実装では文章の部品を編集する。グラフの軸を直接操作する機能や自由な文章の意味判定は含めない。事件の資料本文・数値・既存の解読正解キーは変更しない。

## JSONと判定

正本は `data/cases/*.json` の `v2.board`。`title` / `prompt` / `excerpts` / `tasks` を持つ。

- `excerpts` は `id` / `documentId` / `quote`。引用は資料本文に実在する連続した一節とする。引用元の未読・封印された資料からは選べない。本文にない引用は事件検証で拒否する。
- 各taskは `id` / `title` / `prompt` / `parts` / `fields` / `rules` / `explanation` を持つ。
- `parts` は固定文 `{text}` と編集部分 `{field}`。各fieldを一度ずつ使う。`fields` は `id` / `label` / `original` / `options`。optionsは文の部品で、完成した答えではない。
- `rules` は許容する組み立ての集合。各ルールは全fieldの `values`、`disposition`、必要な引用IDの `evidence`、`explanation` を持つ。複数の証拠経路は別ルールとして記録する。
- 部品の値と文の扱いが合い、いずれかのルールの必要な引用を揃え、その引用元をすべて読んでいれば、そのtaskを確認済みとする。証拠は順不同。同じ文を支える別経路の引用を加えてもよい。どの許容経路にもない引用を足した場合は、根拠との対応を見直す対象とする。
- 不正なID・未読引用・余分なfieldは記録を拒否する。存在する部品で作った誤った説明は保存し、提出後の振り返り対象とする。
- 文の自由な補足は任意で、意味の自動採点をしない。判断の方針や結果の良し悪しも採点しない。
- 必要な資料集合と予算の分析は、各taskの許容ルールの組み合わせから求める。旧グラフの経路を新ボードの完了条件に使わない。

現行5事件には新ボードを定義する。旧 `graph.paths` は互換資料として保持し、boardを持たない旧形式の事件では従来の関係編集・判定を使う。新ボードで旧リンクを作っても達成したことにはならない。

## 保存と互換性

文と証拠の記録は `progress.v2.board[taskId]` に保存する。値・引用・扱いを記録し、再読や再開で復元する。元の記録と異なる編集は、記録ボタンを押すまで未保存と表示する。

事件revision 1から2への移行では、旧状態を履歴に保管する。読んだ資料・調査予算の使用・解読・実験・判断履歴・任意メモは引き継ぐ。旧提出・クリアを新ボードの完了に読み替えず、新ボードの記録と再提出を求める。その他の非互換revisionは既存の保管・再開手順を使う。

## 確認すること

- 正しい文でも証拠不足なら完了せず、証拠だけ正しくても文が違えば完了しない。
- 別の証拠経路、証拠の順番の違い、正しい記述の維持、未確認の判断を扱える。
- 旧リンク・未知の引用・未読資料・余分な部品で完了できない。
- 5事件で予算内の完了経路があり、方針や実験反応を変えても事実判定に影響しない。
- 保存・復元・提出後の編集禁止・取り下げ後の修正が成立する。
- チュートリアル・進捗・ヒント・報告・結果が同じ操作を説明する。
