# 調査中画面の整理 設計案

調査中画面（`src/screens/V2InvestigationScreen.tsx` とデスク部品）を、
**必要な情報だけを見せ、説明を読まなくても操作できる**形に整える設計案。
実装前の合意用。決まったら各節を 1 PR ずつに分けて進める（6 節「進め方」）。

根拠は docs/UI_GUIDE_LINT.md と同じ「UI 設計の基本」（第 1・2・4・5・7・9 章）。
PR #150 で入れた「次にやること」中心の整理と、主ボタンは一画面に 1 つという e2e（`e2e/case01-declutter.spec.ts`）の上に積む。

## 1. 方針

1. **一画面の主役は 1 つ。** 案内文は「次にやること」にだけ置き、押せる主ボタンも 1 つ。ほかは控えめな見た目にする。
2. **状態は図形で見せ、短い言葉を添える。** 既読・未読・開けない・残り回数は、画面のどこでも同じ図形と同じ言葉で示す。アイコンだけにはしない（第 2 章）。
3. **同じ情報を 2 か所に出さない。** 出すなら 1 か所に決め、他は消す（第 2 章「記憶に頼らない」は、消した側を別の場所で覚えさせないことで満たす）。
4. **初見は少なく、慣れたら近道。** 初期表示に入るのは、現在地、次の一手、資料、デスクの 4 つまで。補助機能はメニューへ。
5. **言葉を減らすのであって、なくすのではない。** 読み上げと `aria-label` は今の情報量を保つ。

## 2. いまの画面の棚卸し

case-01 を 1280px と 375px で表示して数えた（2026-11-05）。

| 場所 | いま出ているもの | 同じことを示している別の場所 | 判定 |
| --- | --- | --- | --- |
| ヘッダー | 「STEP 01 / 資料を調べる」、予算ピップ、「調査予算：残り 4 / 4」 | ― | 残す。3 段階のステッパーに拡張 |
| 次にやること | 見出し、案内 1 文、主ボタン | デスク内の案内文、残っていることの一覧 | 残す。案内の唯一の置き場にする |
| 資料カード 1 枚 | 種別名（小見出し）、サムネイル、識別ラベル（CASE 01 / 資料 00（ad）/ 広告 / 無料）、題名、状態アイコン＋「未調査」、「無料で確認」 | 種別 ×3、コスト ×2、状態は見出しの「0 / 6 件確認済み」とも重複 | 4 要素に減らす |
| 資料見出し | 「調査資料」「0 / 6 件確認済み」 | 各カードの既読印 | 件数は残す（進み具合の一目安） |
| デスクタブ | 4 種類の形式のバッジ（0 / 3、0 件、1 / 2 完了、記録済み／未完了） | ― | 形式を 1 つにそろえる |
| 情報解読メモ冒頭 | 使い方 2 文 | 次にやること | 削る |
| 問いの行 | 番号、「問 1 ・ 未回答」、問い、「閉じる／回答する」 | ― | 残す。「未回答」は図形＋言葉に |
| 根拠欄の空状態 | 「答えを選ぶと、もとになる資料と…」 | 冒頭の使い方 2 文 | 1 行に縮めてここだけ残す |
| 証拠ボード冒頭 | 「合っているかどうかは、報告を提出したあとに確かめます」「下線を押すと組み直せます」 | 遊び方の末尾 | 前者は削除、後者は下線のそばへ |
| 残っていることの一覧 | 見出し、残数、注意 2 文、未完了の問いと資料へのボタン列 | タブのバッジ、次にやること、問いの行の「未回答」 | 廃止し、タブ内の印に置き換える |
| 下部バー | 「記録しなくても進めます。」「調査報告をまとめる →」 | 完了時の次にやること | ヘッダーの控えめな出口に移す |
| 遊び方 | 最初の事件の手順 4 つ、原則 4 段落、やり直しボタン | 次にやること、CASE 00 の練習 | メニューに移す。やり直しは危険操作として分ける |
| 最初の判断時の notice | 3 文 | 次にやることの案内 | 削る |

第 5 章の「目を細めて数える」で、塊は 7。目標は 4（ヘッダー、次にやること、資料、デスク）。

## 4. 要素別の仕様

### 4.1 ヘッダー：現在地と予算

- 「STEP 01 / 資料を調べる」を 3 段階のステッパーに置き換える。段階名はホーム画面の 01 資料をめくる / 02 文に証拠を添える / 03 記事にまとめる と同じ言葉にする（第 1 章：同じものは同じ言葉）。
  ただし調査中画面は 01 と 02 を同じ画面でこなすので、ステッパーは **資料を調べる → 報告をまとめる → 結果** の 3 つとし、ホーム側の 3 項目は「遊び方」の説明として残す。
- 現在の段階は塗りつぶしの丸、済んだ段階はチェック、先の段階は白丸。言葉は丸の下に残す。
- 予算はいまのピップのまま。「調査予算：残り 4 / 4」の文字は `aria-label` と、ピップの横の短い「予算 残り 4 / 4」に縮める。数字だけにすると、となりのステッパーの進み具合に見えるので、「予算 残り」は省かない。
- 記事画面の「STEP 02 / 調査報告をまとめる」も同じ部品にする（別 PR）。

### 4.2 次にやること：唯一の案内

- 仕様はいまのまま。案内 1 文と、ボタン 1 つ。
- 操作先がすでに画面に出ているとき（`shown`）はボタンを控えめにする既存ルールを維持する。このときの主ボタンはデスク側の記録ボタン 1 つ。
- 「最初の判断を記録する」段階（`initialExperiment`）の下にある 3 文の notice は削る。必要な情報は案内文 1 文に入っている。

### 4.3 資料カード：5 要素

| 残す | 形 | 言葉 |
| --- | --- | --- |
| 種別 | 種別アイコン（`public/assets/props/<visual>.svg`） | 種別名 1 回（「広告」） |
| 題名 | 太字 | そのまま |
| 番号 | 小さな 2 桁（「00」） | ― |
| コスト | 予算と同じピップ 1 個。無料は「無料」の文字のみ | 読み上げは「調査コスト 1」のまま |
| 状態 | 既読 = チェック（`states/verified.svg`）、未読 = 何も付けない、開けない = 錠（`states/locked.svg`） | 既読「読んだ」、開けない「開けない」。未読は言葉なし |

- 消すもの：種別の小見出し（`doc-tile__kind`）、識別ラベルの「CASE 01」「（ad）」「無料／コスト 1」、状態の「未調査」、「無料で確認／調査コスト 1」の文字。
- 残す理由：識別ラベル（MVP-036）は「サムネイルが同一テンプレートで番号が画像内の極小文字しかない」ために入れた。番号を HTML テキストで残せば目的は満たす。内部 ID「（ad）」は利用者向けの情報ではない（第 9 章：技術用語を画面に出さない）。
- 既読カードは紙の色を少し沈め、チェックを右上に置く。色だけで区別しない（WCAG 1.4.1）。
- 開けないカードは錠と理由 1 行（「予算が足りない」「最初の判断を記録すると開ける」）。理由はカードの上ではなく下に置き、押したときの `role="status"` は維持。
- 資料ダイアログ内の識別ラベルは本文の見出しとして残す（そこでは番号と種別が役立つ）。カード側だけ減らす。

### 4.4 デスクタブ：形式を 1 つに

- バッジは全タブ **「済 / 総」** に統一する。
  - 解読メモ：回答済み / 問いの数（いまと同じ）
  - 証拠ボード：記録済み / 文の数（`linkTarget`）
  - ミニ実験：記録済み / 2
  - 意思決定：記録済み / 1
- 完了したタブは数字の代わりにチェックアイコンと「完了」の 2 文字。
- タブ名にアイコンを添える（解読メモ = `icons/notes`、証拠ボード = `icons/board`、ミニ実験 = `icons/inspect`、意思決定 = `icons/stamp`）。言葉は残す（第 2 章：アイコンには言葉）。
- 「見え方のミニ実験」「情報解読メモ」は「ミニ実験」「解読メモ」に短縮する。パネル内の見出しは長い名のまま。

### 4.5 デスク内の案内文：削る・寄せる

| いまの文 | 置き場所 | 処置 |
| --- | --- | --- |
| 解読メモ冒頭「答えを選ぶと、その答えのもとになる資料が下に並びます。…」 | パネル冒頭 | 削除 |
| 根拠欄の空状態「答えを選ぶと、もとになる資料と、読んだかどうかがここに並びます。」 | 根拠欄 | 「答えを選ぶと、もとになる資料がここに並びます。」の 1 文に |
| 証拠ボード「合っているかどうかは、報告を提出したあとに確かめます。」 | パネル冒頭 | 削除（結果画面で分かる） |
| 証拠ボード「文の下線が付いた部分を押すと、内容を組み直せます。」 | パネル冒頭 | 下線のある文の直下に 1 行で |
| 証拠ボード「まず、調査資料を開いて読みましょう。」 | 出典が空のとき | 残す（空状態の案内。第 7 章） |
| 残っていること「答えを選ぶことと、もとになる資料を読むことの両方が必要です。…」 | 一覧内 | 一覧ごと廃止 |

- 問いの行の「未回答」は、丸の空きと「未回答」の 2 文字のまま。回答済みで根拠未読は「根拠待ち」の 1 語と半分塗りの丸。

### 4.6 残っていることの一覧：廃止

- 示していた内容は、タブのバッジ（残数）、問いの行の状態（どれが残っているか）、次にやること（いま何をするか）ですべて見える。
- 「まだ読んでいない資料」へのボタン列は、問いを開いたときの根拠欄が同じボタンを出している。
- 廃止に伴う変更：`e2e/case01-declutter.spec.ts`、`e2e/first-case-guide.spec.ts`、`src/screens/V2Play.test.tsx` の該当手順を、タブバッジと問いの状態を確かめる形に書き換える。

### 4.7 出口とやり直し

- 「記録しなくても進めます。調査報告をまとめる →」の帯は消す。記録が未完のまま進む経路は「⋯」メニューの「報告へ進む（記録が未完でも）」に残す。
- 記録がそろえば「次にやること」が「調査報告をまとめる →」になる（既存）。
- 「この事件を最初からやり直す」はメニューの最下段、区切り線の下、警告色。確認パネル（`ConfirmPanel`）は既存のまま。
- 「遊び方」はメニューから開く。最初の事件の手順 4 つは残し、原則の 4 段落は CASE 00 と重なるので 2 段落に縮める。

### 4.8 状態の視覚言語（画面全体で統一）

| 意味 | 図形 | 添える言葉 | 使う場所 |
| --- | --- | --- | --- |
| 済んだ | チェック（`states/verified`） | 読んだ／完了／記録済み | 資料カード、タブ、ステッパー、問いの行 |
| まだ | 白い丸（図形のみ） | 未回答（問いのみ） | 問いの行、ステッパー |
| 途中 | 半分塗りの丸 | 根拠待ち | 問いの行 |
| 開けない | 錠（`states/locked`） | 開けない＋理由 1 行 | 資料カード |
| 予算・コスト | 四角のピップ | 数字 | ヘッダー、資料カード |
| 現在地 | 塗りの丸 | 段階名 | ステッパー、選択中タブ |

## 5. 守ること

- docs/UI_GUIDE_LINT.md の規則。`npm run lint:ui` と `npm run lint` を通し、`qa/ui-guide-baseline.json` に足さない。
- 文言は docs/CASE_AUTHORING.md「文章の書き方」。`npm run lint:wording` を通し、`qa/wording-baseline.json` に足さない。
- C-2 のキャラクターと資料サムネイルは触らない。使うアイコンは `public/assets/ui` の既存品のみ。
- 読み上げの情報量は減らさない。カードの `aria-label` は「題名、状態、コスト、理由」の順を維持する。
- 色だけで状態を分けない（WCAG 1.4.1）。コントラストは `lint:ui` の対象。
- 矢印キーでのタブ移動（`useRovingTabs`）と、`sessionStorage` に覚えるタブは維持。

## 7. 受け入れ基準

- 3 秒テスト：初見の人に 1280px の初期表示を見せて「資料を開く」と答えられる。
- 押せる主ボタンは常に 1 つ以下（既存 e2e を維持）。
- 目を細めて数えた塊が 4 つ以下。
- 375×812 の初期表示に「次にやること」とデスクのタブが入る。横スクロールは資料列だけで、ページ全体は横に伸びない。
- 同じ意味の言葉が 1 画面に 2 回出ない（種別、コスト、状態）。
- `npm run lint:ui`、`npm run lint`、`npm run lint:wording`、`npm test`、`python3 scripts/validate_assets.py` が通る。

## 8. 決めてほしいこと

1. 「残っていることの一覧」を完全に廃止してよいか。残すなら、メニュー内に移して初期表示からは外す案にする。
2. 「記録しなくても進めます」の経路をメニューに隠してよいか。意図的に目立たせていたなら、ヘッダー右端の控えめなリンクに残す。
3. 資料カードから内部 ID「（ad）」を消してよいか。QA が ID で資料を指していたなら、`data-document` 属性と `aria-label` には残す。
