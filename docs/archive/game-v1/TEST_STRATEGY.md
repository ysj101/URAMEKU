# 検証計画

## 静的検証

- ケースJSONの必須キー、資料参照、予算、正解の存在をチェック。
- `node --check prototype/app.js` で構文を確認。
- 独立したSVGがXMLとして解釈できることを確認。
- PNGが正しく開けることを確認。

## シナリオ検証

| ID | 手順 | 期待結果 |
|---|---|---|
| T01 | 最初のCASE 01を開始 | 6資料が表示され、残予算4 |
| T02 | 無料資料を開く | 予算は減らない |
| T03 | 有料資料を2度開く | 初回のみ予算消費 |
| T04 | 重要な3資料をピン留め | ボード上に3資料表示 |
| T05 | 必要な2資料を指定 | 2枚が選択中表示 |
| T06 | 検証メモ2問を数値入力し、見出し3断片を組み立てる | 提出可能になる |
| T07 | 必須資料なしで見出しだけ正答 | 掲載承認されない |
| T08 | 証拠・照合・計算・見出しが全部正答 | 掲載承認、解説表示 |
| T09 | 1資料を誤って調査し予算を枯渇 | 調査不能・リセット可能 |
| T10 | リロード | ケース・調査結果が保存される |
| T11 | 保存記録を全削除 | 初期状態に戻る |
| T12 | スマホ幅で操作 | ボタンが隠れず操作可能 |
| T13 | TabキーとEnterキーだけで操作 | ケース選択・資料開閉・採用・提出が可能 |
| T14 | JSONの数字を変更 | テストでロジック矛盾に気づける仕組みを追加する |

## UX検証（未実施）

- 3〜5名に初見プレイを依頼。
- 事件の説明を口頭で補わずに進められるか確認。
- 分かりづらいルールと、難しいけれど納得できる推理を区別。
- ミスした時に次に何を変えるか思いつくか観察。
- 机上の紙の切り抜きが情報の可読性を阻害していないか評価。

計画・観察者シート・同意文は `docs/qa/user-test-plan.md` ほか、記録フォーマットと集計は `qa/user-tests/README.md` と `npm run summarize:user-tests`（MVP-044 で整備。実施は 0 / 5 人）。
