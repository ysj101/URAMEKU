# ゲームルール・採点・難易度

## 1. コアループ

**疑わしい主張を受け取る → 情報を選んで調査 → 重要資料を固定 → 2つの証拠の関係を発見 → 数値の検証メモを作る → 見出しを構成 → 掲載審査 → 振り返り**

### プレイヤーのスキルを要求する点

1. **リサーチ計画**: 初めに何を裏付けるべきか判断。
2. **リソース配分**: 全資料は見られないため優先度を付ける。
3. **数量推理**: 母数、絶対差、相対変化、期間、予算などを比べる。
4. **情報の信頼性**: 取材記録・生データ・広告・口コミの役割を区別する。
5. **編集判断**: 数字が正しくても、表現によって誤解が生じる点を説明する。

## 2. 調査予算

- 事件ごとに4〜5点。資料閲覧時にコストを消費する。
- 無料の初期記事も、確認しない限り証拠ボードへ採用できない。
- 一度閲覧済みの資料は再読でコスト消費なし。
- 調査予算が不足すれば別の資料が開けなくなる。事件リセットで再挑戦可能。
- 低難易度モードや救済の追加調査はMVP後に検討。

## 3. 重要資料の判定

各事件JSONの `required_evidence` をすべてピン留めする必要がある。資料の存在だけではなく、その情報を「証拠として採用する」操作を要求する。MVPでは必要資料3件で共通化しているが、後続版ではグラフで複数経路を許す。

## 4. 証拠の照合

ボード上の任意の資料2枚を押して照合する。資料IDの集合が `required_link` と一致した場合に正解（順序は問わない）。

- 例: `登録台帳` と `翌月の継続状況`。母数をどこから取るかの関係を示す。
- 誤った組み合わせは評価で分かるが、調査中の自動正答表示はしない。
- 事件によって正しい組み合わせの関係が一つに決まらない場合、JSONモデルを更新すべき。強引に一本道へ押し込まない。

## 5. 数値の検証メモ

- 事件内の調査資料から数値を2つ計算して入力する。
- たとえば分母を変えた割合、価格差と割引率、将来費用の合計を問う。
- 数値を推測するのではなく、資料を突き合わせて計算する必要がある。

## 6. 記事組み立て

- 断片8個中、正確な内容の3つを順序を守って選ぶ。
- 不正確な候補は「理由なく全体に一般化」「統計を誤読」「原因を断定」「反対資料の無視」など。
- 調査を経ずに推測だけで見出しを当てても、必要証拠と照合がなければクリア不可。
- 将来の自由記述や複数解を想定し、断片採点は編集エンジンの一部として隔離する。

## 7. スコアとクリア

```text
スコア = (必要証拠の数 × 8、最大24)
         + (必要な照合が成立: 20、そうでなければ0)
         + (正しい数値検証メモの数 × 13、最大26)
         + (正しい順番で置いた断片の数 × 8、最大24)
         + min(6, 残余調査予算 × 2)

クリア = すべての必要証拠を採用
         AND 必要な照合成立
         AND 数値検証メモ2問とも正しい
         AND 見出しの3断片がすべて正しく並んでいる
```

100点の達成は必須ではない。プレイヤーの能力評価ではなく、**事件内の解決手順**を記録するゲームスコアである。

## 8. 事件の難しさを作る原則

- 単に情報を大量にするのではなく、特定の情報同士を比較すると構造が見えるように設計する。
- 目立つ説明や強い言葉が必ずしも重要な根拠とは限らない。
- しかし外れ資料にも調査する合理的理由を用意し、不当に意地悪な罠にしない。
- 答えが解説を読むまで得られない「当てっこ」を避ける。必要な根拠は必ずゲーム内に存在。
- 推理問題を解けた時と、振り返りで気づく心理効果のタイミングを分ける。

## 9. MVPゲームの限界と改善方向

現時点では「ピン留め3件・照合1件・見出し3断片」の型が共通なため、事件が進むと構造が読める可能性がある。継続的に面白い高難易度作品にするなら、次の段階で**証拠間の関係ラベル、推理グラフ、複数の有効な結論、事件ごとの固有操作**を導入する。詳細は `03_EXPANSION_ROADMAP.md`。
