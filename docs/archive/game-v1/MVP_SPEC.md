# MVP仕様書 v0.1 — ウラメク

- ステータス: 企画と操作可能な試作を同梱した初期仕様
- 対象: 個人開発者 / Web MVP
- リリース想定: 6〜8週間の実装・調整（週10〜15時間の作業を想定した概算。実測ではない）

## 1. プロダクト概要

プレイヤーは架空の新聞社「調査編集局」の記者。誇張された広告やニュースの表現、企業資料、統計、証言などを机に広げ、限られた調査リソースの中で裏付けを行う。資料間の関係を自分で推理し、正確な記事を完成させる。ゲーム後に、なぜ最初の表現に引き寄せられたのかを振り返る。

**体験目標:** 「知識の正誤」より「自分で見つけた矛盾」「不完全な情報でいったん判断し、後から更新できたこと」の面白さ。

## 2. コンセプトと独自性

- テーマ: 日常の購買・仕事・マーケティング・ニュースに潜む意思決定のクセ。
- 舞台: 古い新聞・雑誌の切り抜きで埋まった編集部。
- コア: **調査する → 証拠を採用する → 資料を照合する → 数値を計算する → 記事を組み立てる → 採点・振り返り**。
- 差別化: 行動経済学の「名前を答える」のではなく、複数の根拠を使う実践的な推理。
- 倫理: バイアス名は理解の補助であり、ユーザーの人格・能力・認知特性の診断には使わない。

## 3. ターゲットユーザー

- 16歳以上のパズル好き、ニュース・マーケティング・心理学に関心がある人。
- ただの三択や用語暗記に飽きている人。
- 難しい問題に時間をかけることを楽しめる、一般の大人。
- 認知バイアスの知識は不要。プレイに必要な情報は資料として提供する。

## 4. プレイ時間と難易度

- 目標: 導入用ショートケースは1〜3分。標準ケースは5〜10分。難関事件は10〜20分。
- **高難易度を優先**するため、当初の「すべて1〜3分」の条件は設計上のトレードオフとして緩和する。
- 1ケースの中心操作は調査・照合・編集。反射神経や制限時間だけで難しくしない。
- 進捗をローカルに保存し、中断しやすくする。

## 5. ゲームシステム

### 5.1 事件選択

タイトル、推定プレイ時間、難易度、クリア状況。MVPは架空の事件5本。

### 5.2 調査デスク

- 複数の資料カード。初期公開の資料（コスト0）と、調査コストを使う資料を混在させる。
- 情報源、数値、期間、母数、比較対象、反例を読み取る。
- 全資料を無条件に読める設計にしない。予算内で「何を先に確認するか」が戦略になる。
- 調査結果は同じケース内で継続保持、途中離脱しても復元可能。

### 5.3 証拠ボード

- 開いた資料から必要なものをピン留め。
- 2資料を選んで照合関係を作る。
- **MVPでは正しい証拠セットおよび正しい一組の照合で検証**。後続版では根拠の役割（反証・補強・時系列など）や複数リンク、自由な注釈へ拡張する。
- マウスに依存しないクリック/タップ操作を優先し、将来ドラッグ&ドロップを追加する。

### 5.4 数値の検証メモ

- ケースごとに2つの計算・検証課題を用意し、自由数値入力で確認する。
- たとえば「無料体験登録者全体に対する継続率45%」「有料契約者の継続率90%」を資料から算出する。
- 正解数値には案件ごとの許容誤差を設ける。入力の値そのものを心理診断には使わない。

### 5.5 記事作成

- 8つの断片から、根拠に即した3つを正しい順序に組む。
- 誤答の中には「数字自体は正しいが分母がない」「原因を断定している」などの罠を含める。
- 見出し断片の選択は最終段階の一要素。**ゲームの中心はあくまで資料の調査と根拠の照合**。
- 将来は自由入力の見出しと編集レビューを追加するが、自動採点の難しさからMVPでは採用しない。

### 5.6 採点・結果

| 要素 | 配点（最大） |
|---|---:|
| 必要な裏付け資料3件を採用 | 24 |
| 正しい2資料を照合 | 20 |
| 数値検証メモ2問を正しく計算 | 26 |
| 見出し断片3つを正確に構成 | 24 |
| 未使用の調査予算 | 6 |
| 合計 | 100 |

- **クリア条件:** 必要資料をすべて採用 AND 指定照合が正しい AND 数値検証メモ2問の解答が正しい AND 見出し断片と順序がすべて正しい。点数だけではクリアしない。
- 失敗時は不足した種類を示し、再調査・再編集できる。正解公開は任意の操作。
- プレイヤーの生涯能力や「バイアス体質」の判定スコアを計算しない。

### 5.7 ミッション後の学び

- その事件で何が誤解を招きやすかったかを短く解説。
- プレイヤーの実際の選択として記録できるのは、開いた資料・採用証拠・組み立てた見出しのみ。
- 「あなたは○○バイアスが強い」と断定しない。事件の説明を個人診断に変換しない。

## 6. MVP収録ミッション

| ID | タイトル | 主な論点 | 技量 |
|---|---|---|---|
| CASE 01 | 消えた55人の利用者 | 比率の母数とフレーミング | 複数の分母を再計算する |
| CASE 02 | 半額セールの値札 | アンカリング / 参照価格 | 値札と価格履歴を照合する |
| CASE 03 | 8割が支持の正体 | 社会的証明 / 標本選択 | 代表性の限界を見抜く |
| CASE 04 | 取り戻せない開発費 | サンクコスト | 過去費用と将来費用を分ける |
| CASE 05 | 急上昇するグラフ | 表現のフレーミング | 絶対差・相対差と軸を読む |

企業・人物・集計値は架空。ケース内の答えは事実関係に合う記事の構成であり、現実の企業や事件への非難を意図しない。

## 7. ゲーミフィケーション

- 事件クリアと評価ランク: 事件内の達成度。学力診断にしない。
- 「調査記者手帳」: 解決事件、挑戦回数、利用した調査予算。
- 概念図鑑: 事件解決後に関連する考え方を解放。性格類型を生成しない。
- リプレイ: 少ない調査回数での改善や、間違った見出しを修正する挑戦。
- ランキング・対人競争・デイリー課題はMVPに含めない。

## 8. 画面構成

1. タイトル / 事件一覧
2. 事件導入 / 調査予算と初期資料
3. 資料閲覧モーダル
4. 証拠ボード（証拠採用と2資料の照合）
5. 数値検証メモ（2問）
6. 記事編集（3断片の組み立て）
7. 採点 / 解説 / 次の事件

試作では事件一覧をサイドバーにまとめ、調査とボードを1画面に置く。MVP正式版ではスマートフォンでの画面分割を見直す。

## 9. キャラクターとアート

- **シノブ**: 調査記者。好奇心旺盛で慎重、資料に目を通す相棒。記者の帽子・赤い差し色・角張った紙のシルエット。
- **メガ**: データ整理担当。計算と資料の分母確認を助ける。四角い眼鏡と青い差し色。
- **クロ**: 編集部の黒猫。調査中の気づきを非言語で伝える。誤答時に責めない。
- **編集長**: 締切と調査予算の提示役。正解を最初から教えない。

平面の紙の切り絵、網点・掠れを控えめに、モノクロと赤/青の差し色。1画面1主操作、情報の可読性は紙の装飾より優先。画像一式は `assets/` を参照。

## 10. MVPの実装範囲（IN / OUT）

**IN**: 5事件、データ駆動の資料、予算管理、資料閲覧、証拠採用、2資料照合、数値検証メモ、見出し組み立て、合否/理由、端末内保存、簡易キャラクター演出、レスポンシブ表示。

**OUT**: 認証、サーバーDB、決済、ランキング、AI自動生成事件、実在ニュースの自動取り込み、自由文見出しの自動判定、マルチプレイ、音声、運営ダッシュボード、実在人物への心理診断。

## 11. 技術構成

| 項目 | MVP方針 |
|---|---|
| フロント | 静的HTML / CSS / JavaScriptによる試作を同梱。正式化時は React + TypeScript + Vite 推奨 |
| UI | CSS Modules もしくは素のCSS。UIライブラリの大量導入は避ける |
| 状態 | 事件状態を1ケースごとに保持し、ローカルストレージに永続化 |
| コンテンツ | JSON形式、`data/cases/*.json` |
| アセット | SVGを原本とし、必要に応じPNG/WebPを書き出す |
| ホスティング | GitHub Pages等の静的配信 |
| 認証/バックエンド | なし |
| 分析 | なし（個人情報送信を避ける）。正式版で利用目的と同意を設計 |

## 12. 非機能要件

- 文字倍率200%でも判読できることを目標とする。
- 色だけに依存せず、選択中・調査済み・未調査をテキストでも表示。
- 44px程度のタッチターゲットを原則とする。
- シナリオと採点はUIから分離し、単体テスト可能とする。
- 端末内セーブは容量制限と破損時のフォールバックを考慮。
- 外部通信を必須にしない。CDNフォントなしで表示可能。
- 生成AI画像の画面内文字は使わず、文章はHTMLテキストとしてレンダリング。

## 13. 受け入れ基準

- 5件すべてがJSONから読み込める。
- 各事件で予算不足の無条件調査ができない。
- 未閲覧資料は証拠に採用できない。
- 照合は同じ資料2枚を指定できない。
- 正しい証拠、照合、計算、見出しで掲載承認となる。
- 見出しだけ当ててもクリアできない。
- 同じ事件をリセットして再挑戦できる。
- リロード後に進捗が復元でき、全履歴の削除もできる。
- すべてのケースで架空データと明示される。
- PC/スマートフォンで致命的なレイアウト崩れがない。
- 誤答で人格・能力・固定的特性を断定しない。

## 14. 現時点での重要な設計課題

- **クリア判定がパターン化しやすい**: MVP試作は必要3資料＋1リンク＋3断片の共通フォーマット。本実装では事件固有の推論グラフや複数の正当な結論を扱いたい。
- **リソース枯渇で詰む可能性**: リセット操作と、後続版でのヒント/追加調査措置を設計する。
- **モバイルの証拠ボード**: 情報の視認性を保ち、誤タップを減らす。
- **正解が1通りに固定**: 代替的に妥当な記事の扱いはMVPには含まない。今後の拡張で複数解を扱う。
