# JourneyGap：遊び方・CASE00と画面上のCASE01

Issue: https://github.com/ysj101/URAMEKU/issues/201

## 対象と現在の状態

実際のJourneyGap Web SDKを組み込み、既定では無効にする。対象は既存の
`#/tutorial`（遊び方・CASE00）と `#/play/case-06`（画面上のCASE01、平均おこづかい3000円）。
内部ID `case-01` は対象外。他事件のジャーニーは記録しない。
本番受信先の配備、パッケージ公開、マージ・本番公開はこの変更に含まない。
既存の画面・事件JSON・解答・採点・画像は変更しない。

SDKは未公開のため、固定コミットから作成したローカルパッケージを使う。
版・ライセンス・再生成方法は `vendor/journeygap/README.md` を参照。

## 観測の契約

| ジャーニー | 観測順序 | 完了の意味 |
| --- | --- | --- |
| onboarding | 初期画面 → 初回選択を確定 → 条件変更後の選択を確定 → 資料を確認して回答画面へ → 報告確認画面へ → 報告提出 | 正誤を問わず提出した |
| case01-reading | 未提出のCASE01を表示 → 新しい資料を初めて開く | その訪問で資料を新たに開いた |
| case01-report | 未提出のCASE01を表示 → 報告画面を表示 → 報告提出 | 正誤・根拠充足を問わず提出した |

事件の読み取り、証拠ボード、実験など自由な調査順序は一本の順序に押し込まない。
CASE01の「開始」は明示的な新規事件作成ではなく、未提出の事件画面の表示。
画面を離れて戻ると新しい観測試行になる。ロード時点の資料閲覧や提出状態は再送しない。
途中保存から報告画面を開いた場合、その表示から観測し、過去の資料閲覧は補完しない。
CASE00は初期画面で同意が有効な場合だけ開始する。途中で許可した場合は、最初から
やり直すまで開始・過去のステップを補完しない。再描画・StrictMode・回答の見直しで
同じステップを再送しない。CASE01の確認付きリセット、CASE00の最初からの再挑戦は新しい試行。
同意撤回後の再許可も新しい観測になり、撤回中の操作は補完しない。

各試行の期限は開始から30分。期限後の未観測を離脱・困惑・能力・個人特性と断定しない。
観測値には欠落があり、通信、同意撤回、ブラウザ終了も影響する。20開始未満の少人数検証では
生の件数と操作観察を併用し、自動所見を確定的な改善根拠にしない。
集計の分母は対象期間に観測した試行開始数で、人数・全利用者数ではない。

## 同意・プライバシー

対象画面と設定に同じ許可・拒否のボタンを表示する。許可しなくても全機能を使える。
許可後は設定から撤回できる。同意の選択は `urameku-journeygap-consent` に保存する。
SDKの同意キーは `journeygap.consent.v1`、タブ単位IDはsessionStorageの
`journeygap.session.v1`。ランダムなIDは仮名識別子であり、完全な匿名を保証しない。
他タブでの撤回も反映する。端末内記録の全削除は計測を止め、これらのキーも削除する。
撤回は送信待ちのデータを破棄し、送信済みデータを取り戻すものではない。

送信するのは固定のジャーニー・ステップID、画面分類、時刻、イベント・タブ・試行の
ランダムID、スキーマ版とサービス名。独自属性は渡さない。選択肢の内容・正誤、文章、
資料本文、ゲームの保存内容、実URLのパラメーター、アカウント情報は送信しない。
SDKの自動ナビゲーションは許可後に動作するため、対象外画面の遷移は `unknown` 分類として
観測される。他事件のIDやその事件の進行は送らない。Relayは定義済みステップのみ保存し、
ナビゲーションはプロセス内カウンターに留める。

ローカルRelayの保持期間は14日。公開受信先でも14日に揃える。IPは通信先に届き、
Relayの一時的なレート制限に使われる。プロキシのアクセスログは別途確認が必要。
本番有効化前に、実際の運営者・問い合わせ先・受信先・委託先・ログ・削除対応と
プライバシー説明を整合させる（PRD-004/005）。

## 有効化とローカル検証

`npm ci` 後、別ターミナルで次を実行する。DB・トークン・実データはGitに入れない。

```sh
export JOURNEYGAP_ADMIN_TOKEN="$(openssl rand -hex 32)"
node node_modules/@journeygap/relay/dist/main.js \
  --config qa/journeygap.relay.local.json --db /tmp/urameku-journeygap-local.db
```

Web側は次で有効化する。設定は公開情報としてバンドルされる。

```sh
VITE_JOURNEYGAP_ENABLED=true \
VITE_JOURNEYGAP_ENDPOINT=http://127.0.0.1:4318/v1/traces npm run dev
```

http://localhost:5173/#/tutorial で明示的に許可し、CASE00とCASE01を操作する。
公開環境はHTTPSの `/v1/traces` を指定し、受信先のOrigin許可・CSP `connect-src` を合わせる。
ユーザー名・パスワード・クエリー・フラグメント付きURLは使えない。認証用トークンや
上流の資格情報を `VITE_` 変数、ブラウザ設定、URLに入れない。Relayは静的ホスティングでは動かない。

```sh
curl -H "Authorization: Bearer $JOURNEYGAP_ADMIN_TOKEN" \
  'http://127.0.0.1:4318/admin/v1/report?service=urameku&journey=onboarding&days=7'
npm run test:telemetry
```

受入テストは専用ポート・一時DBの実Relayとビルド済みアプリを使用する。
通常のE2Eは無効状態を対象とし、専用テストで実SDKのOTLP送信とRelayレポートを確認する。
設定未指定・無効なURL・SDK読込失敗は計測だけを止め、ゲームは起動する。
ブラウザで拒否・撤回、送信内容に入力が混ざらないこと、対象外事件、再開と再挑戦も検証する。

## 停止・撤去

即時停止は設定の「送信を止める」。配信全体の停止は `VITE_JOURNEYGAP_ENABLED=false` で
再ビルド・再配信する。既配信の開いたページには設定変更が届かないため受信側でも停止を行う。
完全撤去時は `src/telemetry` とTelemetryControls・画面のフックを取り除き、仕様と画面説明を
更新してから依存を削除する。本実装はCLI管理ファイルを生成していないため、CLI uninstallの対象ではない。

検証結果と残る制約は [QA記録](qa/journeygap.md) を参照。
